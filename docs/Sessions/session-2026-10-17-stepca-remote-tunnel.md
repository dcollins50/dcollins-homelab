## What went wrong
- The VLAN Tag field did not stick when 2101 was created in the Proxmox UI. `pct config 2101` showed net0 with no `tag`, so the container was on VLAN1 untagged. Fixed with `pct set 2101 -net0 ...,tag=52,...` and a reboot. Check `pct config` after creating any tagged guest.
- Ping to the VLAN gateway is not a valid test on DMZTunnels: there is no ICMP rule. Use `ip neigh show 10.0.52.x` (REACHABLE or STALE with a MAC means the VLAN path works) and `getent hosts` for DNS.
- step-ca had been down since Oct 10. From 2101, `curl -vk --max-time 10 https://10.0.30.x:9000/health` gave exit 7 (connection refused in 0 ms). On [[pve-int-stepca]] (511) the LXC was running but the `step-ca` container showed `Exited (255) 7 days ago`. Its log is normal 30-second `/health` checks until 2026-10-10 02:42:52 UTC, then nothing: no error or shutdown message. Docker recorded the stop at 02:51:15 UTC with an empty error field, so it looks like an outside stop (LXC, Docker daemon or node), cause not found. Restart policy was `no`, so it stayed down through 511's reboot on Oct 17 15:16. Started with `docker start step-ca` from pve-services (`sudo pct exec 511 -- ...`). After that the same curl from 2101 returned `{"status":"ok"}`, exit 0, which also proves the DMZTunnels `pve_int_stepca` 9000 rule.
- step-ca's TLS certificate seen from 2101: subject `CN=Step Online CA`, 24-hour validity, issued by the intermediate with the known leading-space CN. curl reported `unable to get local issuer certificate` because 2101 does not trust the homelab root. cloudflared private routing forwards traffic without terminating TLS, so 2101 does not need the root; the laptop will.
